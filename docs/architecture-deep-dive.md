# 基于 OneBot 11 与 DeepSeek-V3 的高性能拟真 QQ 群机器人架构指南

本指南总结了一套低成本（Token 消耗暴降 90%+）、高拟真度、自带多模态识图与情绪表情包联动的生产级 QQ 机器人架构与踩坑经验，适合作为二次开发或独立建站项目的架构参考。

---

## 1. 整体架构与数据流拓扑

系统采用**解耦分层架构**，将“网络协议网关”、“机器人核心业务逻辑”与“多模态视觉处理”分离开来：

```
                +---------------------------------------+
                |     QQ 协议底座 (NapCat / OneBot 11)   |
                |  - 支持 Docker / 本地 Linux / Android  |
                |  - 提供 WebSocket API (默认 3001)     |
                +------------------+--------------------+
                                   | 正向 WebSocket
                                   v
+-------------------------------------------------------------------+
|                  Python 异步业务中枢 (bot.py)                      |
|                                                                   |
| 1. 事件分发层:                                                     |
|    - 群消息 / 私聊消息 / 戳一戳 Notice 事件                         |
|    - 管理员鉴权通道 (/root 生产模式 vs /user 拟真群友模式)            |
|                                                                   |
| 2. 上下文与成本优化 (单轮未读设计):                                 |
|    - 放弃全群滚动历史滑动窗口 (避免 Token 爆炸与交叉串台认错人)      |
|    - 仅保留发言人的最新未读输入 (+ 引用回复上下文)                    |
|    - 单次互动输入固定在 200~300 Tokens (降本 90%~95%)             |
|                                                                   |
| 3. 双模态视觉转录链路 (VLM Pipeline):                              |
|    - 遇到图片时，并发调用视觉模型提取画面与文字提炼                |
|    - 转为结构化文本注入 DeepSeek Prompt，低成本实现识图对话         |
|                                                                   |
| 4. 拟真输出与风控防护流水线:                                       |
|    - 单群滑动窗口限频 (60s 内最多 8 条，防腾讯风控禁言)            |
|    - 正则标点分段 (拟真打字手感，首句秒回，次句延迟 0.6~1.0s)        |
|    - 句尾人机括号与句号物理拦截 (彻底消除 AI 痕迹)                 |
|    - 11 类场景的表情包配图 (结构化 base64 单独下发)            |
```

## 2. 核心架构设计与优化策略

### 2.1 单轮轻量未读会话（Token 成本暴降 90%~98%）
* **传统群聊机器人的痛点**：
  * 把全群最近 10~20 条发言全部拼在上下文里；
  * 如果群聊冷清或发言跨度大，不仅极易遗失缓存命中导致 Token 成本指数级上升，而且大模型极其容易“分不清是谁在跟谁说话”，经常把 A 的发言当成 B 的背景，甚至产生幻觉串台。
* **架构改造**：
  1. **状态解耦**：彻底剥离长篇滚动群消息历史；
  2. **发言聚焦**：每次只将当前说话者的输入（若使用了 QQ 引用回复，则带上被引用的那一条消息）组装成单轮会话；
  3. **长期记忆托管**：用户的个人特征、好感度与长期设定交由轻量持久化 JSON（如 `user_memories.json`）维护，由后台协程异步评估更新，主响应零延迟且 Token 永远稳定在 200~300 tokens。

### 2.2 文本模型的识图链路（VLM 异步转录）
* **原理**：DeepSeek-V3 等纯文本模型不具备原生图片输入能力，直接接入会报错 400；
* **落地实践**：
  1. 正则匹配消息中的 `[CQ:image,url=...]` 提取图片直链；
  2. 预先压缩或降分辨率（建议长边限制在 512~768px），通过高性能轻量视觉模型（如 Gemini Flash 或 Qwen-VL）提炼图片要点（10~30 字以内，如 `“表情包配字‘这期拉了’，蓝发少女委屈撇嘴形象”`）；
  3. 将解析结果作为 `[用户发送了图片: ...]` 伪装文本，与用户的发言一同提交给 DeepSeek；
  4. 最终输出既保留了 DeepSeek 的神级文风，又完全具备了秒级多模态“看懂表情包/截图”的能力。

### 2.3 拟真打字体验与分段发送
* **拒绝整块大段输出**：真人群聊很少一次性发出一长串小作文；
* **分段规则**：
  * 遇到换行符或强标点（`[!！?？~。]`）时，截取为最多 2 段；
  * 第一段附带 `@用户` 立即发出；
  * 根据第一段字数动态计算延迟（`min(1.2, max(0.5, len(seg) * 0.04))` 秒），随后发出第二段；
  * 若处于工程维护（`/root`）模式或输出 Markdown 代码块，则自动跳过分段，保持完整代码单条发出。

## 3. 生产避坑铁律（核心踩坑总结）

### 踩坑 1：表情包发送千万严禁拼接在文本末尾
* **惨痛教训**：
  * 将 `[CQ:image,file=base64://...]` 字符串直接拼接在文字后方发送；
  * 若发信逻辑中配置了单条消息字数保护（如防止刷屏的 `len > 200` 截断），base64 字符串会在第 197 处被截断为 `...`；
  * 导致 CQ 码破损，群里会直接裸露发出几百个字符的残缺 base64 乱码代码，极度尴尬。
* **正确做法**：
  * 文字发完后，表情包必须使用 OneBot 11 原生的**结构化图片消息对象**单独发出：
  ```python
  payload = {
      "action": "send_group_msg",
      "params": {
          "group_id": group_id,
          "message": [{"type": "image", "data": {"file": f"base64://{b64_data}"}}]
      }
  }
  ```

### 踩坑 2：彻底消灭 AI“句末括号”与油腻报幕腔
* **现象**：许多二次元/群友提示词模板喜欢教导大模型“开玩笑在句尾加括号（）”，这会导致 LLM 产生严重的模式坍塌，句句末尾都带 `（` 或 `（）`，人机味扑面而来；
* **解决方案（双重拦截）**：
  1. **Prompt 层面**：明确写入严禁在句尾包含任何形式的括号；
  2. **清洗管道硬拦截**：在消息最终出栈前，用正则硬切：
  ```python
  def sanitize_reply(text: str) -> str:
      text = text.strip()
      while text.endswith(("。", ".")):
          text = text[:-1].strip()
      # 物理剔除句尾常见的人机味残留括号
      return re.sub(r'[\(（][\)）]?\s*$', '', text).strip()
  ```

### 踩坑 3：单群发信硬限频与腾讯风控红线
* **现象**：群聊活跃时，多个群友连续艾特或触发追问，机器人在 1 分钟内密集发出 10 条以上消息，会被腾讯官方网关风控检测，轻则吞消息、群禁言，重则冻结账号；
* **解决方案**：
  * 引入 **60 秒滑动窗口限频器**（单群 60s 内最多发 8 条）；
  * 超过配额时静默丢弃或进入 30 秒冷静期，随性吐槽一句“闹麻了，排队艾特我干嘛，让本鲸宝喘口气”，符合人设，也不会踩风控。

### 踩坑 4：持久化文件的高并发写锁
* **现象**：群友记忆与好感度在后台异步更新时，如果两名群友几乎同时互动，多个协程同时 `open('user_memories.json', 'w')` 会产生竞态，导致 JSON 损坏为空 `{}`；
* **解决方案**：
  * 所有读写必须加持 `asyncio.Lock()`；
  * 写入文件时先写临时文件再进行原子重命名（`os.replace`），保证文件永不损坏。

## 4. 表情包与情绪的对应关系

将表情包资源目录按场景分类，基于用户输入与大模型输出的关键词动态选择：

| 触发场景 | 匹配关键词示例 | 推荐目录分类 |
| :--- | :--- | :--- |
| **二次元 / 游戏** | 原神、鸣潮、崩铁、星铁、米哈游、感觉不如... | `_genshin` |
| **理财 / 股市** | 股票、A股、基金、大盘、跌、亏、抄底、韭菜 | `_stock` / `_green` |
| **大涨 / 赚钱** | 涨停、大涨、红了、发财、赚了 | `_red` |
| **嘲笑 / 吃瘪** | 哈哈、笑死、绷不住、乐子、吃瘪 | `_laugh` |
| **职场 / 打工** | 上班、加班、打工、老板、周一、下班、干活 | `work` |
| **休息 / 熬夜** | 睡觉、晚安、好困、困了、熬夜、失眠 | `sleep` |
| **要饭 / 红包** | 给钱、v我50、红包、乞讨、打钱 | `givemoney` |
| **炸毛 / 生气** | 气、才不是、骂人、炸毛、咬人、烦、哼 | `angry` |
| **神了 / 逆天** | 草、闹麻了、你无敌了、逆天、6 | `fool` |
| **嫌弃 / 吐槽** | 笨蛋、傻、二货、嫌弃 | `baka` |
| **亲近 / 开心** | 喜欢、好耶、开心、真棒、爱了、摸摸 | `happy` |
| **疑惑 / 懵圈** | ？、?、啥、为什么、为啥、看不懂、卡了 | `confused` |

*注：建议在筛选表情包时过滤掉 >1.2MB 的大文件，防止过大的 base64 撑爆 WebSocket 帧。*

## 5. 管理员生产模式与娱乐模式快速切换

为了让机器人既能在水群时充满趣味，又能在开发者需要时充当正经干活的助手，建议设计双运行模式：

```python
# 模式定义
# 1. /user 模式: max_tokens=150, temperature=0.85, 严格 1~2 句拟真群友口吻
# 2. /root 模式: max_tokens=1500, temperature=0.3, 专业工程师严谨口吻，支持长篇代码与日志诊断，跳过分段发送
```
管理员可通过私聊或群聊发送 `/root` 或 `/user` 随时切换。
